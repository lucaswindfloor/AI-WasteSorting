# AI-WasteSorting

E09 工控机的 M01 设备接入与采集、M02 时空基准与标定、M03 推理运行与模型管理。使用 C++20 和标准库。

```sh
make test
```

## M01 接入契约

- 在同一条串行执行路径调用 `AcquisitionService`。先由实际设备适配器配置设备并回读，再以核验后的 `Config` 启动。硬件回调进入该路径前的队列由集成方限容。发生 SDK 队列丢失时，集成方需要留存设备和受影响区间。
- `SyncInput` 和 `PacketView` 接收已规范化的 IF-001、IF-002 元数据。适配器负责依据实际 SDK 和 ICD 提供帧布局、逐行触发证据、设备状态与媒体格式。传入视图在调用期间有效即可，采集核心每个包复制一次原始字节。源时钟、主机收到数据的时间和服务的单调时钟分别保留。成帧、压缩解码和实际曝光换算依赖设备。适配器目录提供规范化输入的校验入口，实机调用待接入。
- **同步输入约定。** 同一个同步会话与计数世代内，IF-001 输入按触发 ID 递增，允许重复。适配器需先验证这一保证，或在进入服务前做有界重排。只有证明 ID 连续分配后才打开连续号检查。已知首触发和已核验的最终触发可以分别通过 `first_expected_trigger` 与 `close` 传入，用于检测整段或首尾的同步事件缺口。跳号不能证明丢失发生在哪一层。
- **匹配期限。** 相机先到时，自该触发首个候选进入服务起等待同步事件；同步出现后，自同步进入服务起再等待相机。到达期限时先收口，再处理新输入。调用方在空闲时也应按固定周期调用 `advance`，把周期、串行队列、两段等待和分段延迟计入端到端时限。输出顺序按完成时间，消费方按触发键和源行区间索引。超期和冲突通过诊断交付。重复检测保留有限历史，配置需覆盖实装最大重传范围；源行与触发的映射在一个会话内应稳定。
- **数据质量。** `MISSING` 表示该触发缺少经过验证的预期输入。存在可定位但证据不足的触发提示时，对应分量为 `UNKNOWN`；无法定位的原始观测随诊断交付，不能据此判定相机漏曝。有效负载的触发归属和 M02 的观测可用性分别核验。E05 按源会话独立交付，保留单位、范围引用及缺测状态。
- **分段与背压。** 将 `Output.segments` 交给 M02 和 M09，各消费者保留独立的共享引用，M09 达到持久化条件后释放。随同 `Output.diagnostics` 交付缺口、晚到证据和容量拒收信息。发布后的在线段不可变。调用方消费每次调用返回的输出，限容自己的队列，并对诊断做必要的持久化。采集核心限制原始字节、待配对数和在途段数，超过硬限时报告受影响的触发或观测。单个完整项可超过分段字节目标，仍受全局原始字节硬限。调用方从健康快照获取水位和最近有效输入，由工艺路径执行限料或停料，实际尾量和阈值通过联调确认。
- **换代与收尾。** 先停止或切换设备输入，处理已授权的最后数据，再调用 `close`。重连、计数世代重建或格式变化后，回读并核验设备设置，用更高的 `generation` 启动。每个回调携带注册时的世代与源会话。已经发布的段跟随原世代配置，其原始负载继续计入同一服务的缓冲预算。

## M02 接入契约

- 先用 `CalibrationService::install` 注册 M08 已核验的参数快照，再用 `process` 处理 M01 的采集段。快照按运行和配置世代选择，并严格核对设备身份、会话、固件、SDK、格式和编码器世代。调用方串行安排安装、退役和处理。排队中的旧段继续使用原快照，直到退役。回退使用新配置世代关联旧参数。M09 应保留完整快照和处理时用到的同步及环境证据，以便在新实例回放。
- 每个时钟映射以设备、会话、时钟域和 `time_basis` 为条件，描述设备原始时钟到主机单调时钟的比例、锚点、有效区间和误差。同步事件使用 `trigger`。相机或 E05 的 `time_basis` 由已核验设备契约给出。只有源时间映射或已核验触发延迟模型可用于换算曝光。主机收件时间随原始观测保留。
- `ProcessContext::sync_window` 可提供来自同一运行及配置世代的有界同步事件窗口。观测计数采用已核验的设备曝光计数，或通过同世代、同方向、时间间隔满足条件的锁存样本插值。插值误差和最高计数速率来自台架数据。无可靠换算时保留单路几何和原始数据，公共覆盖为空。输出保留源计数、目标参考和已用位移，供后续继续跟踪。
- RGB／HSI 按相机列和生效的参考高度投影。高度层之间只在已批准的范围内插值，残差应覆盖插值误差。单层标定只覆盖该高度。当前输出为列坐标和符合时空误差界的共同覆盖，保留各路采样位置供下游使用。E05 按自己的时刻转换到皮带坐标。需要把独立观测对到选定参考时，通过 `ProcessContext::independent_reference` 提供已核验的同步事件。M04 结合物料身份决定哪些 E05 表面可用于目标，以及何时采用相应高度层，M02 不自动把附近表面分给目标。
- 规范化载荷的 `transport_layout` 为 `packed`。HSI 支持 `U8`、`U16LE` 和 `F32LE`，按列存放连续波段；E05 支持 `XYZ_F32LE` 和 `HEIGHT_F32LE`，每条观测对应一行，单位为毫米。可选掩膜每个样本一个字节，0 表示缺测，其他值表示可检查。RGB 掩膜按列，HSI 按列及波段，E05 按点。SDK 的其他布局需要通过实装接口适配。
- 用 `ProcessContext::environment` 提供 IF-008 和采集设置核验结果。暗白参考支持按波段或按列与波段索引。先核对曝光时的设置、环境与参考健康，再提供校正值及逐样本质量。校正值保留计算结果及范围，模型输入约束由 M03 核对。
- `transform_point` 和 `transform_pose` 使用指定快照、坐标系和工具，原样保留输入位置的时间和参考计数。位姿请求明确选择 TCP 或法兰输出。材料运动沿带的处理已由上游参考确定，坐标变换仅改变坐标表达。
- 将 M01 另外交付的缺口和诊断随对应段送入 `ProcessContext::acquisition_diagnostics`。结果保存源段引用，使用方应按在线及归档生命周期释放结果。

## M03 接入契约

- M08 将已批准的模型包整理为 `Manifest` 和模型字节。该对象声明实际制品校验值、运行时和精度、RGB／HSI 路径、波段顺序、校正级别、归一化、窗口、裁切与缩放、类别和输出含义。安装检查后端报告的制品身份并验证预热输出。实际后端负责根据模型字节校验制品及适配运行引擎，仓库提供了后端接口与模拟实现。
- `activate` 核对 M01 的设备格式及 M02 的标定快照，再将模型绑定到运行和配置世代。一个世代可使用 RGB、HSI 或两者各自的模型，也可单独使用联合模型。兼容性校验逐项匹配波段顺序和暗白参考版本。
- 首版窗口依据已确认连续分配的共同触发号组装。M08 提供首触发锚点，窗口按长度和步长划分。先到的行按自己的位置等待，可证明的同步缺口保留空位。调用方仅在知道某范围已收口时调用 `seal_through`。等待达到上限后，按模型掩膜规则交付部分有效输入或报告失效。超出预设前视范围会报告范围及原因，大跨度间断需要分段确认或重新启动采集世代。
- 分路 RGB 使用 packed RGB8。分路 HSI 使用 packed U8、U16LE 或 F32LE，校正后的值与逐样本质量由 M02 提供。联合模型在 RGB 网格上使用 M02 给出的列对应关系，分别构建 HWC 浮点张量和逐样本掩膜。预处理支持裁切、最近像素中心取样、填充和逐通道归一化。模型输出使用半开像素框和可选的逐实例二值掩膜。回映结果带源行、源列、B 系位置、观测基准和已应用的位移；同一源位置在窗口内只投影一次，跨窗口仍可据来源关联。
- `ingest` 接收 E09 单调时钟上的绝对截止，窗口取所含数据的最早截止。调用方根据端到端预算给出截止，并在空闲时调用 `advance`。实机应注入同一时域下的 `Clock`，以计入处理期间经过的时间；测试可直接推进时钟值。队列按截止顺序调度，并约束等待数量、执行数量和张量及来源映射的内存。窗口失去在线资格后，后台仍在使用的输入会保留至作业结束。
- 换版使用新配置世代，并为新世代明确首触发。旧世代未提交的窗口在退役时收口报告。已提交窗口可按获准策略排空，也可立即停止其在线交付。运行中的作业继续持有自己的模型和输入。回退需要新配置世代，可以复用此前已核验的模型版本。
- M03 输出窗口级轮廓和材质证据，由 M04 进行跨窗口同件判定。E05 独立表面仍通过 M02 的交接进入 M04。整机使用前需接入批准的模型及真实推理后端，确认支持的布局、预处理、分支组合和实测负载。
